k6 SUMMARY — LandMark, этап 4
================================

k6 на тестовой машине НЕ установлен (проверка: `k6 version` -> command not found),
поэтому полноценный нагрузочный прогон не выполнялся. Готовый k6-скрипт приложен:
  tests/load/basic_load.js   (10 VU, 35 c, пороги: ошибки <1%, p95 < 1000 мс)
Запуск при наличии k6:
  k6 run tests/load/basic_load.js

Вместо прогона k6 выполнено эквивалентное измерение времени ответа через curl
(tests/load/perf_curl.sh, 30 запросов на эндпоинт). Результат (см. perf_curl_summary.txt):

  GET /healthz          avg = 5.4 ms   p95 = 7.1 ms   max = 23.5 ms   (200)
  GET /v1/places        avg = 7.9 ms   p95 = 8.7 ms   max = 30.7 ms   (200)
  GET /v1/places/{uuid} avg = 5.7 ms   p95 = 7.1 ms   max =  8.3 ms   (404)
  POST /v1/auth/login   avg = 9.2 ms   p95 = 23.0 ms  max = 26.0 ms   (401)

Вывод: на лёгкой нагрузке все ключевые эндпоинты отвечают за единицы миллисекунд,
p95 < 25 мс, ошибок нет. Порог p95 < 1000 мс из k6-скрипта выполняется с большим запасом.
Поведение под устойчивой нагрузкой (ramp до 10+ VU) следует проверить отдельным
прогоном k6 на CI (см. RISK_REGISTER.md, R-06).
