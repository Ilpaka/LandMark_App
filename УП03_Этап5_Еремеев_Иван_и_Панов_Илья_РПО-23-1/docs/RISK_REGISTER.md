# RISK_REGISTER.md — LandMark, этап 5 (безопасность и эксплуатация)

Минимум 6 рисков: 3 по безопасности (S) и 3 по эксплуатации (O). Каждый риск связан с конкретной проверкой этапа 5.

## Риски безопасности

| # | Риск | Причина / доказательство | Вероятность | Влияние | Мера снижения |
|---|------|--------------------------|-------------|---------|---------------|
| S-1 | Утечка `.env`/секретов в Git | Файл с реальными секретами может случайно попасть в коммит | Низкая | Высокое | **Снижено:** `.env*` и `backups/`/дампы/логи в `.gitignore`; в git только `*.example` с `change_me_*`; проверка `git status` перед коммитом (скрин 01–03) |
| S-2 | Открытый CORS (`*`) | `CORS_ORIGINS=*` — любой сайт мог обращаться к API из браузера (скрин 07) | Средняя | Высокое | **Снижено:** `CORS_ORIGINS` ограничен конкретным origin; в проде — реальный домен. Доп.: добавить security-заголовки (X-Frame-Options, HSTS, CSP) |
| S-3 | Уязвимая зависимость | `govulncheck`: `golang-jwt/jwt/v5` 5.2.1 (GO-2025-3553, DoS при разборе JWT), `redis/go-redis` 9.7.0, `crypto/tls` (Go 1.25.5) | Средняя | Среднее/Высокое | **Частично снижено:** JWT обновлён до 5.2.2. Остальное — в RECOMMENDATIONS (redis→9.7.3, Go→1.25.7) |
| S-4 | Раскрытие OTP-кода в ответе API | `register` возвращает `dev_code` (на demo-стенде `APP_ENV=production`) | Средняя | Высокое | Включать только на demo (флаг/нестрогая среда); в проде код слать только по email/SMS. Внесено в реестр (на этой ветке фикс из этапа 4 откатан) |

## Риски эксплуатации

| # | Риск | Причина / доказательство | Вероятность | Влияние | Мера снижения |
|---|------|--------------------------|-------------|---------|---------------|
| O-1 | Потеря данных (нет резервной копии) | Без регулярного backup данные БД невосстановимы | Низкая/средняя | Высокое | **Снижено:** `scripts/backup.bat` (`pg_dump`) + `scripts/restore.bat`; восстановление проверено, число строк совпало (скрин 08–09). Доп.: расписание backup (cron) |
| O-2 | Сервис не поднимается после сбоя/перезапуска | Зависимость от готовности БД/Redis; не у всех сервисов healthcheck | Средняя | Среднее | `restart: unless-stopped`, `depends_on: condition: service_healthy`, `scripts/check_deploy.bat`, проверка логов |
| O-3 | Лишние/публично открытые порты | Grafana/Prometheus/Mailpit/MinIO слушают `0.0.0.0` без аутентификации (скрин 10) | Средняя | Среднее | БД(5432)/Redis(6379)/бэкенд уже только во внутренней сети. Операторские UI — привязать к `127.0.0.1` или закрыть фаерволом/обратным прокси с авторизацией |
| O-4 | Слепой мониторинг | Prometheus не собирает метрики с большинства сервисов (из этапа 4) | Средняя | Высокое | Открыть `/metrics`, настроить алерты; не полагаться на текущий мониторинг как на достоверный |

**Итого: 8 рисков (4 безопасность + 4 эксплуатация).** Снижено в рамках этапа: S-1, S-2, S-3 (частично), O-1.
Остальные — в `RECOMMENDATIONS.md`.
