# 01 · Продукт: роли, сценарии, MVP-границы

> Этот файл задаёт **что** мы делаем. Все остальные файлы отвечают на вопрос **как**.
> Единый источник UX: `WIKI/design/wanderlog_screens.html` (68 экранов).

## 1. Vision (одно предложение)

> **Wanderlog** — это мобильное приложение, объединяющее карту достопримечательностей, личный журнал поездок и архив воспоминаний в едином пространстве, где каждая запись привязана к месту и хронологии путешествия.

## 2. Ценностные предложения

| Ценность | Аудитория | Пояснение |
|---|---|---|
| Единый контекст «место + журнал» | Самостоятельные путешественники | Сейчас точки, фото и заметки разнесены по 3-5 приложениям |
| Личный архив поездок | Все пользователи | Возврат к истории, поиск по дате/месту/тегу |
| Краудсорсная карта POI | Активные пользователи | Можно предложить новую достопримечательность → модерация → публикация |
| Офлайн-режим | Путешественники в плохой связи | Кэш карты, черновики записей, отложенная синхронизация |

## 3. Роли пользователей

### 3.1 Гость (`role=guest`, без аутентификации)

Доступно:
- Карта `MP-01` с публичными POI
- Просмотр карточек POI `MP-04`, `MP-08`
- Поиск `SR-01..03` по публичным POI
- Категории, фильтры на карте `MP-02`

Заблокировано (через CTA «Войдите чтобы…»):
- Создание поездки, записи, добавление в избранное, предложение POI

### 3.2 Пользователь (`role=user`, после регистрации)

Доступно всё, что у гостя, плюс:
- Поездки `TR-*`, журнал `JR-*`, маршруты `RT-*`, избранное `FV-*`
- Профиль и настройки `PF-*`
- Уведомления `NT-*`
- Предложение публичной POI `MP-05..07` (уходит в очередь модерации)
- Загрузка медиа

### 3.3 Администратор (`role=admin`, добавляется вручную через SQL/CLI)

Имеет всё от пользователя, плюс:
- Раздел `AD-01..04`: дашборд, очередь модерации, карточка модерации, управление категориями
- Через `auth-service`: блокировки, аудит — но эти эндпоинты переиспользуются из Tennis-шаблона.

> Примечание: admin — это **роль в JWT** (claim `role=admin`), отдельной админ-консоли нет; админ заходит в обычный мобильный клиент, ему просто открывается дополнительная вкладка.

## 4. Ключевые пользовательские истории (User Stories)

### US-01 Регистрация и первый вход
- **As a** новый пользователь
- **I want to** создать аккаунт по email+пароль и подтвердить email через 6-значный OTP
- **So that** мои поездки сохраняются между устройствами
- **AC:** реализовано в auth-service по образцу Tennis (см. `05_AUTH_SERVICE.md`); экраны `AU-01..06`.

### US-02 Просмотр карты и POI
- **As a** гость или пользователь
- **I want to** видеть карту с пинами достопримечательностей и фильтровать по категории
- **So that** найти интересное место рядом
- **AC:** `MP-01..08`; backend в `07_PLACES_SERVICE.md`.

### US-03 Создание поездки
- **As a** пользователь
- **I want to** создать поездку с названием, датами и регионом
- **So that** записывать впечатления, привязывая их к этой поездке
- **AC:** `TR-01..06`; backend в `08_TRIPS_SERVICE.md`.

### US-04 Запись в журнал
- **As a** пользователь
- **I want to** добавить текстовую запись с фотографиями и тегами в активную поездку
- **So that** сохранить воспоминание
- **AC:** `JR-01..06`; backend в `09_JOURNAL_SERVICE.md`. Запись по умолчанию привязана к ближайшей POI или координате.

### US-05 Маршрут на день
- **As a** пользователь в поездке
- **I want to** собрать список точек на день и видеть маршрут на карте
- **So that** не забыть ничего и оптимизировать путь
- **AC:** `RT-01..04`; точки маршрута — это записи `TripStop` в `08_TRIPS_SERVICE.md`.

### US-06 Избранное
- **As a** пользователь
- **I want to** сохранять интересные POI/поездки/записи в избранное и видеть их списком и на карте
- **So that** быстро возвращаться к ним
- **AC:** `FV-01..03`; backend в `11_FAVORITES_SERVICE.md`.

### US-07 Предложение нового POI
- **As a** активный пользователь
- **I want to** предложить новую достопримечательность с фото и описанием
- **So that** обогатить общую карту
- **AC:** `MP-05..07` создают POI со статусом `pending_moderation`; modеration-service `13`.

### US-08 Модерация (admin)
- **As a** админ
- **I want to** просматривать очередь предложений и одобрять/отклонять их
- **So that** карта оставалась полезной и без спама
- **AC:** `AD-01..04`; backend в `13_MODERATION_SERVICE.md`.

### US-09 Офлайн-режим
- **As a** пользователь без связи
- **I want to** видеть закэшированные точки и создавать черновики записей
- **So that** не терять моменты
- **AC:** `ST-03`, `PF-06`; локальная очередь в Flutter (`Drift` + retry-policy).

### US-10 Синхронизация и удаление
- **As a** пользователь, желающий сменить устройство или удалить аккаунт
- **I want to** видеть статус синхронизации и иметь кнопку «Удалить аккаунт» с подтверждением
- **So that** контролировать свои данные
- **AC:** `PF-05`, `PF-06`, `PF-08`; auth-service: `DELETE /v1/auth/account` (уже есть в Tennis).

## 5. MVP-границы

### В скоупе MVP

- Email+пароль регистрация и подтверждение через email-OTP (Tennis уже умеет)
- Карта с публичными POI (создаются админом + предлагаются юзерами)
- Создание/редактирование поездки
- Создание записи журнала с 1-10 фото
- Избранное (POI и поездки)
- Базовые push-уведомления (старт поездки, успешная синхронизация, одобрение POI)
- Очередь модерации для админов

### Сознательно ВНЕ MVP (помечать заглушками экранов / `not_implemented`)

- SMS-вход / телефонная регистрация (опционально, оставляем эндпоинты, но в UI скрываем за feature flag `feature.phoneAuth=false`)
- Социальный вход (Google, Apple) — подключение в Phase 3
- Активная навигация по маршруту с реальной маршрутизацией (`RT-03`) — в MVP это статическая отрисовка списка
- Реакции и комментарии под записями — Phase 4
- Шеринг через `Share sheet` (`MD-03`) — Phase 4
- Multi-region carrier для гео-поиска — заменяем box-фильтрацией на квадрат
- Платные функции — отсутствуют в MVP

## 6. Нефункциональные требования

| Категория | Требование |
|---|---|
| Производительность | API p95 < 300 мс на чтение, < 600 мс на запись (без учёта upload) |
| Доступность | 99.5% (single-region), graceful shutdown SIGTERM ≤ 10 c |
| Масштабируемость | Каждый сервис stateless; Postgres single-master; Redis sentinel-ready |
| Безопасность | См. `22_OBSERVABILITY_SECURITY.md`; OWASP Mobile Top-10 для клиента |
| Логирование | JSON structured (`slog`), уровень из env `LOG_LEVEL` |
| Трассировка | OpenTelemetry, OTLP/HTTP в Tempo/Jaeger через `OTEL_EXPORTER_OTLP_ENDPOINT` |
| Метрики | Prometheus `/metrics` per service |
| Локализация клиента | Только `ru` для MVP, заложить `en` (`flutter intl`) |
| Доступность UI | Минимум: контраст AA, HitArea ≥ 44pt, поддержка Dynamic Type |
| Поддерживаемые платформы | iOS 14+, Android 8+ (API 26), Flutter 3.16+ |

## 7. KPI и success-метрики

- Time-to-first-trip ≤ 3 минут от установки до создания первой поездки
- Drop-off на onboarding ≤ 25% (`SP-02..04` → `AU-01`)
- Conversion гость→пользователь ≥ 30% при первой попытке создать запись
- Offline-устойчивость: 100% черновиков записей синхронизируются после восстановления связи
- Audit-events: 100% значимых auth-действий пишутся в `auth_audit_log` (унаследовано из Tennis)
