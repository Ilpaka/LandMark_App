# Инструкция по запуску проекта LandMark (Wanderlog)

Документ описывает запуск проекта **с нуля на другом компьютере**. Проект состоит
из двух частей: **backend** (Go-микросервисы в Docker) и **client** (Flutter).

---

## 1. Предварительные требования

| ПО | Версия | Проверка | Зачем |
|---|---|---|---|
| Docker Desktop | 24+ | `docker --version` | Запуск всего backend и инфраструктуры |
| Git | любой | `git --version` | Клонирование репозитория |
| Flutter SDK | 3.24+ (Dart 3.4+) | `flutter --version` | Сборка и запуск мобильного клиента |
| Эмулятор Android / симулятор iOS | — | `flutter devices` | Устройство для запуска клиента |

> Для запуска backend нужен **только Docker** — Go устанавливать не требуется,
> сборка идёт внутри контейнеров. Flutter нужен только для клиента.

---

## 3. Запуск backend

### 3.1. Настройки (необязательно)

Все переменные имеют безопасные значения по умолчанию, поэтому для локального
запуска файл `.env` не обязателен. При желании можно создать его:

```bash
cp "УП03_Этап1_Фамилия_Имя_Группа/.env.example" backend/.env
```

→ скриншот `screenshots/03_env_example.png`

### 3.2. Сборка и старт контейнеров

Убедитесь, что Docker Desktop запущен, затем:

```bash
./start-backend.sh
# эквивалентно:
cd backend && docker compose up -d --build
```

Первая сборка занимает несколько минут (загрузка образов и компиляция Go-сервисов).
→ скриншот `screenshots/02_install_dependencies.png`

### 3.3. Проверка, что backend поднялся

```bash
docker compose ps                       # все сервисы в статусе Up / healthy
curl http://localhost:8080/healthz      # ожидается: HTTP 200
```

→ скриншот `screenshots/04_success_run.png`

Доступные адреса после запуска:

| Назначение | Адрес |
|---|---|
| API Gateway (точка входа клиента) | http://localhost:8080 |
| Mailpit — входящие письма (OTP, сброс пароля) | http://localhost:8025 |
| MinIO Console — хранилище медиа | http://localhost:9001 (minioadmin / minioadmin) |
| Grafana — мониторинг | http://localhost:3000 (admin / admin) |
| Prometheus | http://localhost:9090 |

### 3.4. Быстрая проверка API (smoke-test)

```bash
# Вход под демо-администратором — вернёт JSON с access_token
curl -X POST http://localhost:8080/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@apple.com","password":"AdminPass123456"}'

# Публичный список достопримечательностей (без токена) — HTTP 200
curl http://localhost:8080/v1/places
```

## 4. Запуск клиента (Flutter)

```bash
cd landmark_app
flutter pub get          # установка зависимостей
flutter devices          # проверить, что есть устройство/эмулятор
flutter run              # запуск приложения
```

По умолчанию клиент обращается к `http://localhost:8080` (на Android-эмуляторе —
к `http://10.0.2.2:8080`). Изменить адрес можно при запуске:

```bash
flutter run --dart-define=API_BASE_URL=http://<адрес_сервера>:8080
```

→ скриншот `screenshots/05_app_working.png`

## 5. Остановка

```bash
cd backend
docker compose down           # остановить контейнеры (данные сохраняются в томах)
docker compose down -v        # остановить и удалить тома (полный сброс данных)
```

## 6. Типичные проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен | Запустить Docker Desktop и повторить |
| Контейнеры падают (Exited 137) при сборке | Нехватка памяти Docker | Увеличить лимит RAM в Docker Desktop (≥ 6 ГБ) |
| `Connection refused` на :8080 | Сервисы ещё стартуют | Подождать 10–20 c, проверить `docker compose ps` |
| Клиент не видит backend на Android | Эмулятор использует `10.0.2.2` | Адрес уже задан по умолчанию; проверить, что backend запущен |
